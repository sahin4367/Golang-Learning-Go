CUSTOME ERROR : nedir
bu error odur ki , bizim proyekitmizde lahiyemizde demeli eger bir problem bas vererse , 
biz sadece desek ki "XETA BAS VERDI"
bu meselenin helli deyil ve biizm hansi sahede hansi valudesa yeni fielde , xeta bas verib 
bunu bilmek ucun mueyyen returnlerle cavablar qayatramliyaiq  mesajler daha dogrusu~!

biz bidene *struct* quruuruq ve orda veririk 
type ValidationsError struct {
    Field string
    Value string
    Message string
} // bu hele sadece bir struct -dir. Melumat saxlayir.
bir Error() methodu teyin elave edirik ? 
func (e *ValidationsError) Error() string {
    return e.Field + ": " + e.Message
} // indi bu struct artiq error interfaceni impliment edir .
Gonun  gozunde bu struckt artiq bir ERRORDUR.~!
func yasYoxla(yas int) error {

ERROR WRAPPING - | 
bu nedir tutaq ki bizim 3 mertebeli binamiz var 
3 -cu metrebe - main() - her seyi idare edir~!
2 -ci mertebe - istifadeAd() - istifadeci adlari tapir~!
1 -ci mertebe - dbDenOxu() - databaseden oxuyur~!

eger birinci mertebede xeta bas verse , nece olacaq . Bu xeta yuxari qalxacaq main() -e catmalidir~!
xeta yuxari qalxanda yolda ne bas verdiyini bilmirikde onu hell etmek ucun !
1 de deyildiki : "database de xeta bas verdi "
2 de deyildiki : "database de xeta bas verdi "
3 de deyildiki : "database de xeta bas verdi "

main() -e catinca "database de xeta bas verdi " bele bir sey verir , axi bu main()  harada? 
hansı funksiyada? nə vaxt? — heç nə bilmir.
WRAPPING ILE HELL : 
1-ci mərtəbə → "database xətası"
2-ci mərtəbə → "istifadəçiAl: database xətası"     ← öz kontekstini əlavə etdi
3-cü mərtəbə → "main: istifadəçiAl: database xətası" ← tam yol görünür
